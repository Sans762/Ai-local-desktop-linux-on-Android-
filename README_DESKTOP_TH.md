# Local AI Linux Desktop v0.6 — วิธีใช้ (ไทย)

**แอป Android Native บน ARM64 โดยไม่ต้องใช้ Termux และไม่ต้อง Root**

## สิ่งที่มี
- Alpine Linux ARM64 userland ผ่าน PRoot (ใช้ kernel Android เดิม ไม่ใช่ VM)
- Linux Desktop แบบกราฟิก: TigerVNC + Openbox + ทาสก์บาร์ tint2 + PCManFM + XTerm
- ดู/กดเมาส์/พิมพ์บน **Linux Desktop ภายในแอป Android** ผ่าน noVNC
- ให้คอม Windows/Linux/Mac รีโมทเข้ามาที่ Linux Desktop ผ่าน VNC (เมื่อเปิดบริการ)
- เปิดเว็บ AI จากมือถือ (127.0.0.1:18788) และจากคอมในเครือข่ายส่วนตัว (IP มือถือ:18789)
- GGUF AI แบบออฟไลน์ + Linux Agent วางแผนคำสั่งพร้อมขั้นตอนกดยืนยันก่อนรัน
- ไม่มี Accessibility Service / ไม่มี MediaProjection / ไม่ควบคุม Android UI

## เริ่มใช้งานทีละขั้น
1. ติดตั้ง APK ใหม่ แล้วเปิด **Control Center**
2. ตั้งรหัสผ่านเว็บ AI อย่างน้อย 8 ตัวอักษร
3. กด **ติดตั้ง Alpine Linux จาก APK** (ไม่ต้องใช้อินเทอร์เน็ต)
4. กด **ติดตั้ง Linux Desktop** (ต้องต่ออินเทอร์เน็ตครั้งแรกเพื่อโหลดแพ็กเกจ)
5. หากต้องการใช้ AI ให้ดาวน์โหลดหรือ import ไฟล์โมเดล GGUF แล้วกด **เริ่มบริการ AI**
6. ตั้ง **รหัสผ่าน VNC** (8 ตัวอักษรแรกเป็นรหัสที่ VNC ใช้จริง) แล้วกด **เริ่ม Linux Desktop**
7. รอให้แอปแสดงสถานะ **Linux Desktop ready** และ IP สำหรับเชื่อมต่อ
8. บนมือถือกด **เปิด Linux Desktop บนมือถือ** แล้วใช้รหัส VNC เดิม
9. บนคอม: ติดตั้ง VNC Viewer เช่น TigerVNC Viewer แล้วกรอก **IP ที่แอปแสดง:5902** พร้อมรหัส VNC
10. บนคอม: เปิด **http://IP-มือถือ:18789** ในเบราว์เซอร์ แล้วล็อกอินด้วยรหัสผ่านเว็บ AI

ตัวอย่าง: ถ้าแอปแสดง IP 192.168.1.25
- Remote Desktop บนคอม: `192.168.1.25:5902`
- Web AI บนคอม: `http://192.168.1.25:18789`
- Web AI บนมือถือ: `http://127.0.0.1:18788`

**ต้องใช้ IP ที่แอปแสดงจริง ไม่ใช่ IP ในตัวอย่าง** และมือถือ/คอมต้องอยู่ในเครือข่ายส่วนตัวที่เชื่อมถึงกันได้ หรือมี VPN ส่วนตัวที่ตั้งค่าไว้แล้ว

## ความปลอดภัย
- เริ่ม/หยุด VNC บนมือถือเองเท่านั้น มี notification พร้อมปุ่ม Stop
- ตัว VNC Server รับการเชื่อมต่อจาก loopback; แอป Android เปิด relay ไปยัง Wi-Fi/LAN หรือ VPN ส่วนตัวเท่านั้น
- VNC ใช้รหัสผ่าน ไม่ได้เข้ารหัสทราฟฟิก; HTTP AI บน LAN ก็ไม่ได้เข้ารหัสเช่นกัน **ใช้เฉพาะเครือข่ายที่เชื่อถือได้** หรือเครือข่าย VPN ส่วนตัวเท่านั้น
- ห้าม forward พอร์ต 5902, 18789 ออกสู่อินเทอร์เน็ต และอย่าพิมพ์รหัสผ่านในเครือข่ายสาธารณะ
- หากเปลี่ยน Wi-Fi/IP ให้หยุดแล้วเปิด Desktop อีกครั้ง
- หากแอปถูก Android ปิด ให้เปิดใหม่จากหน้า Control Center
- Linux desktop ทำงานในพื้นที่แอป ไม่ได้ทำให้ Android กลายเป็น Linux ทั้งระบบ

## ข้อจำกัดที่ยังต้องทดสอบ
- **Build APK ผ่าน ไม่ใช่การทดสอบบนมือถือจริง**; การรัน PRoot, Xvnc, Openbox และการรีโมทบน Android 17 ยังต้องทดสอบ
- Linux/Desktop อาจถูกระบบประหยัดพลังงานของ Android หยุด
- ไม่ใช่เดสก์ท็อปที่เร่งด้วย GPU, ไม่มี systemd/Docker หรือสิทธิ์ Root จริง
- ต้องมีพื้นที่ว่างสำหรับโมเดล GGUF และโปรแกรม Linux Desktop เพิ่มจากขนาด APK
- บาง VPN อาจต้องเลือก/ตั้งค่า IP เครือข่ายเพิ่มเติม
- AI ไม่ใช่ ChatGPT และคำสั่ง Linux Agent ต้องได้รับการอนุมัติจากผู้ใช้ก่อน
